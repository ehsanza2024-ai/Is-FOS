# مازندشت | Mazandasht

سامانه فارسی و محلی با **هسته مستقیم Excel**؛ رابط ثابت بدون اسکرول بدنه، انتخاب نام به جای کد، باسکول، خرید/فروش عادی، موجودی، بانک، دفتر چرخه چک، سند دوبل، ورود فایل بانکی و پشتیبان.

> **وضعیت: نسخه توسعه ۰٫۵، نه نسخه نهایی تأییدشده حسابداری.** اطلاعات تاریخی خصوصی در Git قرار نمی‌گیرند. اکسل‌های اصلاح‌شده تاریخی و پرونده بازبینی جداگانه به مالک تحویل می‌شوند؛ آنها به دفترکل جدید به‌صورت خودکار مهاجرت نشده‌اند.

## شروع سریع

نیاز: Python 3.11+ و مرورگر جدید. نصب اولیه وابستگی‌ها اینترنت می‌خواهد؛ اجرای روزمره نیازی به اینترنت، CDN، ورود ابری یا AI ندارد.

```sh
python -m venv .venv
# Linux / macOS
.venv/bin/python -m pip install -r requirements.lock.txt
# Windows: .venv\Scripts\python -m pip install -r requirements.lock.txt
```

**اجرای دفتر واقعی خالی (محلی):**

```sh
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

آدرس محلی: `http://127.0.0.1:8000`؛ نام کاربری اولیه `admin`. رمز تصادفی در ترمینال اولین راه‌اندازی چاپ می‌شود. برای تعیین رمز دلخواه، **پیش از اولین اجرا** `MAZANDASHT_PASSWORD` را در محیط سیستم تنظیم کنید (حداقل ۱۲ نویسه؛ رمز را در Git ذخیره نکنید). پس از ایجاد پایگاه کاربران، تغییر این متغیر رمز کاربر موجود را عوض نمی‌کند. برای تغییر رمز از فرمان مدیریت زیر استفاده کنید.

```sh
.venv/bin/python -m scripts.manage_user --name admin --role admin
```

**نمونه آموزشی با اطلاعات کاملاً مصنوعی:**

```sh
.venv/bin/python -m scripts.seed_demo runtime/demo
MAZANDASHT_DEMO=1 .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

محیط آموزشی ورود نمی‌خواهد؛ هرگز فایل واقعی یا رمز واقعی در آن نگذارید. برای پیش‌نمایش می‌توان host را `0.0.0.0` گذاشت؛ نصب واقعی را بدون TLS و تنظیمات شبکه به اینترنت عمومی باز نکنید.

## کار با اکسل بدون نرم‌افزار

فایل قالب یا «خروجی اکسل» را در Excel باز کنید و Guide را بخوانید. تعاریف با نام انتخاب می‌شوند؛ کدهای داخلی پنهان‌اند. Events، Weigh و Checks دفاتر ورود هستند؛ Journal، Trial، Stock و Controls فرمول دارند. محاسبه را روی Automatic بگذارید و پیش از اتکا به اعداد Recalculate All انجام دهید. در حالت مستقل، کنترل‌های سرویس، نقش و قفل اتمیک اجرا نمی‌شوند؛ تاریخ، موجودی، سند معکوس و توازن باید کنترل شوند. موتور Excel واقعی در این محیط آزموده نشده است.

نرم‌افزار و Excel را هم‌زمان روی فایل واحد ویرایش نکنید. نرم‌افزار فایل `runtime/local/Mazandasht.xlsx` را می‌خواند؛ کپی دانلودشده خودکار با آن همگام نمی‌شود.

## اصلاح مجموعه تاریخی

پس از قراردادن **کپی** آخرین ۱۴ فایل در یک پوشه، شامل Info.xlsx:

```sh
.venv/bin/python -m scripts.repair_legacy /path/to/source /path/to/repaired
```

خروجی را در پوشه جدا نگه دارید. در Entry/Details، ستون‌های جدید «انتخاب نام» در انتهای شیت هستند و ستون کد قبلی پنهان شده است. `repair-report.json` نشانی دقیق را می‌دهد؛ برای نمونه Weigh.Entry نوع سبد در AR و Basket.Entry در U است. همه ۱۴ فایل باید کنار یکدیگر باشند؛ به‌روزرسانی پیوندها و محاسبه کامل باید در Excel واقعی بررسی شود.

نام سبد/محصول/حساب/بانک/انبار/ارز به Sync مرجع پیوند دارند (تا ظرفیت ۳۰۰ رکورد مرجع قدیمی). عنوان قرارداد، نرخ کارکرد و بارهای منبع snapshot زمان اصلاح هستند؛ افزودن/تغییر آنها نیازمند به‌روزرسانی نگاشت و آزمون مجدد است. این محدودیت را با همگام‌سازی خودکار اشتباه نگیرید.

## آزمون و ساخت بسته

```sh
.venv/bin/python -m pytest -q
.venv/bin/python -m scripts.build_delivery
```

۴۵ آزمون در محیط این تحویل گذشت. آزمون مرورگر روی سه اندازه صفحه انجام شد؛ Excel Desktop، Windows 7، چاپگر واقعی و نصب‌کننده EXE آزموده/ساخته نشده‌اند.

## موارد مهم تکمیل‌نشده

مهاجرت و تطبیق کامل تاریخچه، صافی و posting مالی شراکت، حسابداری خودکار چرخه چک، ارزش‌گذاری خودکار موجودی، انتقال/امانی انبار، گردش کامل سبد، حقوق قانونی، بستن دوره، صورت‌های مالی رسمی، Print Builder، تم تیره، همگام‌سازی شبکه و AI متصل. فهرست دقیق در [قرارداد ادغام](docs/CONSOLIDATED_SPEC_FA.md) و [وضعیت تحویل](docs/DELIVERY_STATUS_FA.md) است.

اطلاعات ناقص را با صفر، نرخ حدسی یا سند ساختگی پر نکنید. اجازه ادامه توسعه، جایگزین صحت و پذیرش داده مالی نیست.
