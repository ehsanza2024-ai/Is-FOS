# نصب مرکزی و اتصال داشبورد — نسخه توسعه ۰٫۶

این راهنما برای **ثبت فقط در برنامه نصب‌شده روی سیستم مرکزی** و **نمایش گزارش در Safari/iOS و مرورگر موبایل/کامپیوتر** است. نصب روی کامپیوتر واقعی مالک در این محیط انجام نشده؛ اسکریپت‌ها، کنترل‌های سرور و گزارش‌ها آزموده شده‌اند، اما پوسته Windows/WebView2 و Excel Desktop هنوز پذیرش عملی می‌خواهند.

## ۱. بسته را کجا باز کنم؟

بسته خصوصی را در پوشه‌ای ثابت و محلی، مثلاً `C:\Mazandasht`، باز کنید و وارد زیرپوشه `Software` شوید. اجرای برنامه از داخل ZIP، OneDrive/Dropbox، پوشه شبکه یا فایل Excel مشترک مجاز نیست. پوشه را پس از ساخت میان‌بر جابه‌جا نکنید. مسیرهای نمونه فرض می‌کنند ترمینال داخل `Software` است.

بسته شامل سورس برنامه، همه اسکریپت‌های این نسخه، فهرست وابستگی‌های ثابت هسته و وابستگی‌های پوسته، قالب خالی و راهنماها است. بسته خصوصی علاوه بر آنها اصل‌های دریافت‌شده، ۱۴ Excel اصلاحی و فایل بازبینی تاریخچه را دارد. **نصب اولیه آنلاین است**: باینری Python، WebView2 و همه wheelهای وابسته داخل ZIP نیستند؛ نصب‌کننده آنها را دریافت می‌کند. این یک نصب‌کننده اسکریپتی است، نه EXE/MSI امضاشده یا بسته آفلاین جامع.

## ۲. Windows مرکزی

هدف پیشنهادی Windows 11 نسخه ۶۴بیتی و Python **3.11** است. Windows 7 هدف این نصب نیست. Windows 10 تنها با پشتیبانی/به‌روزرسانی امنیتی مناسب و آزمون محلی قابل بررسی است؛ سازگاری تأییدشده فرض نشود.

۱. روی `install.bat` دوبار کلیک کنید. اسکریپت PowerShell کنار برنامه، Python 3.11 و Microsoft Edge WebView2 Runtime را بررسی می‌کند؛ اگر موجود نباشند با `winget` دریافت می‌کند. نصب پیش‌نیاز سیستم ممکن است تأیید UAC بخواهد. اگر winget موجود نیست، Python 3.11 و WebView2 Runtime را از منابع رسمی نصب و ترمینال را دوباره باز کنید. خطای دانلود، نصب را متوقف می‌کند؛ داده قبلی پاک نمی‌شود.
۲. محیط `.venv` و وابستگی‌ها از `requirements.lock.txt` و `requirements-desktop.txt` نصب می‌شوند.
۳. رمز `admin` را تعاملی، حداقل ۱۲ نویسه، وارد و تکرار کنید. رمز در فرمان، فایل تنظیمات یا Git نوشته نمی‌شود. ساخت کاربر `viewer` با رمز مستقل پیشنهاد می‌شود؛ فقط گزارش‌خوان است.
۴. اگر دفتر واقعی قبلاً وجود داشته باشد، بازنویسی یا مهاجرت نمی‌شود. نصب دوباره، کاربران موجود را خودکار بازنشانی نمی‌کند. اگر بخشی از نصب قطع شد، پیام را بخوانید؛ برای افزودن viewer از مدیریت کاربر استفاده کنید.
۵. میان‌بر **Mazandasht Central** روی Desktop ساخته می‌شود. آن را یا `start.bat` را اجرا کنید. پنجره تمام‌صفحه مستقل WebView باز می‌شود؛ ابتدا با admin وارد شوید. برای بستن، `Alt+F4` و تأیید خروج؛ تا هنگام ثبت، برنامه را نبندید.

هیچ افزونه Excel، افزونه مرورگر، Node.js، npm، بانک مالی جداگانه یا اینترنت روزانه لازم نیست. Excel روی دستگاه برای استفاده مستقل/بازبینی فایل‌های XLSX لازم است، نه برای اجرای محاسبات سرویس Python. فقط وابستگی‌های نصب اولیه اینترنت می‌خواهند؛ اجرای شبکه محلی به اینترنت وابسته نیست.

### تغییر یا ایجاد کاربر

برنامه و هر سرویس داشبورد را ببندید؛ در `Software` اجرا کنید:

```bat
manage-user.bat viewer viewer
manage-user.bat admin admin
```

رمز تعاملی است. برای نقش‌های مرکزی، نقش سوم فرمان می‌تواند `operator` یا `finance` باشد؛ **هیچ‌کدام روی داشبورد راه ثبت ندارند**. پس از تغییر رمز، هر دو سرویس را دوباره اجرا کنید تا نشست‌های قبلی باطل شوند.

## ۳. Linux مرکزی

پوسته به نشست گرافیکی GTK/WebKit نیاز دارد؛ روی سرور headless باز نمی‌شود. مسیر خودکار بسته‌های سیستم برای **Debian 12 با Python 3.11 سیستم** تنظیم شده، نه همه توزیع‌ها:

```sh
chmod +x install.sh start.sh start-dashboard.sh
./install.sh --system-deps
./start.sh
```

گزینه `--system-deps`، با sudo بسته‌های `python3.11`, `python3.11-venv`, `python3-gi`, `gir1.2-gtk-3.0`, `gir1.2-webkit2-4.1`, `libgirepository1.0-dev` را نصب می‌کند. بدون این گزینه هیچ تغییر apt انجام نمی‌شود و پیش‌نیازها باید قبلاً نصب باشند. محیط مجازی با `--system-site-packages` ساخته می‌شود تا GTK سیستم در دسترس باشد. در توزیع دیگر باید نسخه Python و افزونه‌های GI یکسان/سازگار باشند؛ صرف کپی `.venv` از دستگاه دیگر کافی نیست. پوسته گرافیکی Linux در محیط ساخت اجرا نشده است.

مدیریت کاربر:

```sh
.venv/bin/python -m scripts.manage_user --name viewer --role viewer
```

## ۴. دو سرویس با دو اختیار متفاوت

| مسیر | نشانی/اتصال پیش‌فرض | اختیار |
|---|---|---|
| ثبت مرکزی | loopback سیستم مرکزی، `127.0.0.1:8000` | فقط پنجره نصب‌شده با نشست خصوصی یک‌بارراه‌اندازی و سپس نام کاربری/رمز |
| داشبورد | نشانی LAN/VPN سیستم مرکزی، پورت `8001` | فقط گزارش؛ ورود اجباری در دفتر واقعی |

`start` هر دو را اجرا می‌کند. داشبورد، مستقیم **همان `Mazandasht.xlsx`** را زیر قفل می‌خواند، نه کپی پشتیبان یا پایگاه مالی جدا. تازگی گزارش با اثر انگشت نسخه و زمان دریافت مشخص است؛ صفحه باز هر ۳۰ ثانیه تازه می‌شود. بستن پنجره مرکزی هر دو پردازش متعلق به آن را متوقف می‌کند؛ سیستم نباید Sleep شود. برای نمایش بدون پنجره ثبت می‌توان **به‌جای start**، `start-dashboard.bat` یا `./start-dashboard.sh` را اجرا کرد؛ پیش از اجرای دوباره start آن را ببندید. این راه فقط گزارشِ دفتر موجود را می‌دهد و هیچ ثبت مالی ندارد.

مرورگر معمولی حتی روی PC مرکزی، بدون نشست خصوصی پنجره نصب‌شده به رابط ثبت دسترسی ندارد. این جداسازی جای امنیت سیستم‌عامل نیست؛ مدیر یا بدافزارِ دارای دسترسی به فایل‌ها/حافظه سیستم مرکزی می‌تواند داده یا سورس را تغییر دهد. آن رایانه باید حساب OS اختصاصی، رمز، به‌روزرسانی و دیسک/پشتیبان امن داشته باشد. فایل XLSX را share نکنید. برنامه را با `app.main:app` مستقیم منتشر نکنید؛ آن ماژول پیاده‌سازی داخلی است. پورت ۸۰۰۰ را proxy/forward نکنید و proxy-header را برای آن فعال نکنید. هیچ ثبت/همگام‌سازی آفلاین موبایل وجود ندارد.

## ۵. اتصال iPhone، iPad، Android و PC

۱. سیستم مرکزی و دستگاه گزارش‌خوان در شبکه خصوصی امن یا VPN باشند. IP پایدار برای سیستم مرکزی در روتر رزرو کنید؛ نام/IP واقعی با `ipconfig` در Windows یا `ip addr` در Linux مشخص می‌شود.
۲. نشانی **سیستم مرکزی** را وارد کنید، مثلاً اگر IP واقعی آن `192.168.1.20` بود: `http://192.168.1.20:8001`. عدد نمونه را بی‌دلیل کپی نکنید. `localhost` در گوشی یعنی خود گوشی، نه سیستم مرکزی.
۳. Windows Firewall به‌صورت خودکار تغییر نکرده است. فقط اگر شبکه واقعاً Private و قابل‌اعتماد است، مدیر در PowerShell با دسترسی Administrator می‌تواند این قانون محدود به subnet محلی را اضافه کند:

```powershell
New-NetFirewallRule -DisplayName 'Mazandasht report dashboard private LAN' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8001 -Profile Private -RemoteAddress LocalSubnet
```

برای شبکه VPN، به‌جای بازکردن همه IPها، محدوده واقعی VPN را صریح محدود کنید. پورت ۸۰۰۰ قانون ورودی شبکه نیاز ندارد. فایروال را کامل خاموش نکنید.
۴. با کاربر گزارش‌خوان و رمز تعریف‌شده در مرکز وارد شوید. در iOS، Safari → Share → **Add to Home Screen** یک میان‌بر می‌سازد. این برنامه بومی App Store نیست؛ افزونه و نصب بسته روی گوشی لازم ندارد. Safari/WebView واقعی iOS در محیط ساخت آزموده نشده است.

### HTTPS و اتصال خارج از محل

HTTP نمونه فقط برای LAN آزمایشیِ قابل‌اعتماد است؛ رمز و گزارش روی HTTP رمزگذاری نمی‌شوند. برای اطلاعات واقعی روی شبکه نامطمئن **HTTPS با گواهی مورداعتماد دستگاه‌ها** و برای دسترسی بیرون **VPN امن، ترجیحاً همراه HTTPS** به کار ببرید. هیچ port-forward عمومی روی مودم پیشنهاد نمی‌شود. این بسته VPN، دامنه و گواهی برای شبکه شما صادر نمی‌کند.

اجرای مستقیم HTTPS با گواهی و کلید تهیه‌شده توسط مدیر:

```bat
start.bat --tls-cert C:\certs\dashboard-fullchain.pem --tls-key C:\certs\dashboard-key.pem
```

معادل Linux:

```sh
./start.sh --tls-cert /secure/dashboard-fullchain.pem --tls-key /secure/dashboard-key.pem
```

سپس `https://نام-مطابق-گواهی:8001` را باز کنید؛ Cookie ورود Secure خواهد بود. هشدار گواهی را در دستگاه واقعی نادیده نگیرید. برای reverse proxy TLS، فقط داشبورد را پشت proxy محلی قرار دهید، نه ثبت مرکزی؛ `MAZANDASHT_DASHBOARD_HOST=127.0.0.1` و `MAZANDASHT_HTTPS_ONLY=1` را پیش از start تنظیم کنید. proxy باید Host اصلی را نگه دارد، درخواست‌های غیر HTTPS را به HTTPS هدایت کند و به داده/سورس روی دیسک مسیر ندهد. نشست‌ها حافظه‌ای‌اند؛ فقط یک worker اجرا شود. دسترسی و تمدید گواهی باید روی شبکه واقعی آزمایش شود.

## ۶. گزارش‌ها و حدود معنی آنها

داشبورد شامل نمای مدیریت، سود و زیان دوره، وضعیت مالی مدیریتی، مانده اشخاص، صورت‌حساب شخص با مانده اول/گردش/پایان، بانک، رسید فاقد سند متصل، چک جاری، موجودی و تراز گردش دوره است. تاریخ‌ها شمسی و بر مبنای **تاریخ سند** هستند؛ برگشت ممکن است تاریخ اصل را داشته باشد، پس اینها snapshot تاریخی غیرقابل‌تغییر نیستند. صورت‌حساب شخص به انتخاب یک شخص نیاز دارد. مبلغ روی سرور ریال صحیح است؛ گزارش JSON اعداد صحیح را رشته می‌دهد و UI از BigInt استفاده می‌کند تا جمع بزرگ از دقت JavaScript خارج نشود؛ تومان فقط نمایش است.

- فیلتر شخص بر گردش مالی/سود و زیان و اشخاص/رسید/چک اعمال می‌شود. وضعیت مالی، مانده بانک و موجودی، همیشه کل مجموعه تا تاریخ پایان‌اند، نه مانده جعلی بانک برای یک شخص. تاریخ شروع بر گردش دوره اثر دارد؛ بر مانده کل تا پایان اثر ندارد.
- «رسید فاکتورنشده» در این نسخه یعنی قبض ورود/خروج که **سند خرید/فروش قطعی فعال با شناسه منبع متصل ندارد**. دفتر مستقل وضعیت فاکتور کاغذی وجود ندارد؛ ممکن است فاکتور مستقلی وجود داشته باشد اما به دلیل نبود پیوند، قبض همچنان در این فهرست دیده شود. پس این عنوان تضمین نبود فاکتور کاغذی نیست. سند برگشت‌خورده مصرف فعال قبض نیست و قبض می‌تواند با سند اصلاحی تازه متصل شود.
- وضعیت چک‌ها جاری است، نه مانده چک به تاریخ گذشته؛ وصول خودکار سند بانک ایجاد نمی‌کند.
- کاربران viewer این نسخه گزارش‌های کل مجموعه را می‌بینند. این **پرتال مشتری با جداسازی اطلاعات مشتریان** نیست. برای نمایش به مشتری بیرونی تا پیاده‌سازی مجوز سطری از این نسخه استفاده نکنید.
- چاپ/PDF گزارش مجاز است، ولی APIهای ثبت/اصلاح/ورود فایل/بازیابی/کاربر و حتی دانلود فایل خام دفتر یا پشتیبان روی داشبورد وجود ندارند. اکانت admin هم روی این سرویس فقط می‌خواند.

## ۷. داده، پشتیبان و خطایابی

مسیر پیش‌فرض دفتر `Software/runtime/local/Mazandasht.xlsx` است. `auth.sqlite3` صرفاً کاربران است؛ پوشه `backups` تصاویر کامل قبلی دفتر و `logs/services.log` خطای سرویس‌ها را نگه می‌دارند. مسیر را می‌توان با متغیر محیط `MAZANDASHT_DATA` به یک پوشه محلی امن تغییر داد؛ همان متغیر برای مدیریت کاربر و نصب/اجرای دوباره نیز تنظیم شود. رمز را در آن متغیر قرار ندهید.

- نصب واقعی دفتر خالی می‌سازد؛ اگر فایل فعلی موجود باشد آن را پاک نمی‌کند. فایل نمونه عمداً به ثبت نصب‌شده راه داده نمی‌شود. **تاریخچه واقعی هنوز مهاجرت مالی نشده**؛ فایل‌های قدیمی را صرفاً به `Mazandasht.xlsx` تغییرنام ندهید.
- پشتیبان پیش از هر تغییر، دقیقاً bytes دفتر قبل از همان تغییر است؛ نداشتن تراکنش بعدی طبیعی است. JSON برنامه قدیمی و staging تاریخچه، دفتر یکپارچه فعلی نیستند. صفحه راهنمای مرکزی مسیر/هش دفتر و تعداد/اختلاف شناسه‌های آخرین پشتیبان را نشان می‌دهد؛ این مقایسه، تطبیق کامل مبالغ یا تشخیص قطعی اختلاف فایل گزارش‌شده شما نیست.
- برای Excel مستقل یا تعویض دفتر، **همه سرویس‌ها، از جمله داشبورد** را ببندید؛ از کل پوشه داده پشتیبان بگیرید. Excel خارجی تابع FileLock سرویس نیست. فایل داده روی دیسک مرکزی بماند، نه share شبکه. پشتیبان خارجی رمزگذاری‌شده برای خرابی کل دستگاه لازم است.
- اگر پورت اشغال باشد launcher متوقف می‌شود و پردازش دیگر را نمی‌کشد. نمونه قبلی start/start-dashboard را ببندید. اگر ورود پس از تغییر رمز کار نمی‌کند هر دو سرویس را restart کنید. مسیر، نام کاربری و log را بررسی کنید؛ فایل و رمز واقعی را در GitHub عمومی نفرستید.
- نصب به‌عنوان Windows Service، شروع خودکار هنگام روشن‌شدن، failover، نگه‌داری خودکار پشتیبان و مانیتورینگ سرویس در این ساخت پیاده نشده‌اند. برای نمایش دائمی، برنامه یا سرویس فقط‌خواندنی باید باز بماند.

## چک‌لیست پذیرش روی سیستم مقصد

- [ ] نصب Python/WebView2/وابستگی‌ها بدون خطا؛ میان‌بر واقعاً پنجره تمام‌صفحه را باز کند.
- [ ] تعریف نام واقعی، ثبت یک گردش کنترل‌شده و مقایسه Excel/گزارش/پشتیبان روی **کپی آزمایشی**.
- [ ] مرورگر PC مرکزی روی مسیر ثبت 403 بگیرد؛ فقط برنامه نصب‌شده پس از ورود ثبت کند.
- [ ] روی گوشی/PC دیگر، مشاهده گزارش با ورود درست کار کند و درخواست ثبت حتی با admin رد شود.
- [ ] پورت ۸۰۰۰ از LAN قابل‌استفاده نباشد؛ HTTPS/VPN و گواهی مورداعتماد دستگاه‌ها تأیید شود.
- [ ] چاپ، iOS واقعی، برگشت، قطع اتصال و بازیابی روی دستگاه دیگر آزموده شوند.
- [ ] ۱۴ Excel اصلاحی با موتور Excel مقصد محاسبه/پیوند/کنترل شوند و تاریخچه با حسابدار تطبیق شود.

تا گذر این پذیرش‌ها و حل موارد مالی باز، نسخه توسعه است؛ این راهنما مدرک نصب انجام‌شده یا تأیید نهایی حسابداری نیست.
